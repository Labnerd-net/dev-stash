# Plan: Cloudflare Workers Migration

## Context

The app previously deployed via Dokploy with a standalone Docker/Node.js setup. The Neon migration (drizzle-orm/neon-http + @neondatabase/serverless) removed the last Node.js-only database dependency. This plan migrates the deployment target to Cloudflare Workers using @opennextjs/cloudflare. better-auth edge compatibility was confirmed (requires nodejs_compat flag). Shiki requires a rewrite to avoid WASM (unsupported on Workers by default) and reduce bundle size.

---

## Steps

### 1. Create branch
```
git checkout -b claude/feature/cloudflare-workers-migration
```

### 2. Scaffold Workers config
Run the OpenNext migration command — it installs `@opennextjs/cloudflare`, creates `wrangler.toml`, and creates `open-next.config.ts`:
```
npx @opennextjs/cloudflare migrate
```
Review generated files before proceeding.

### 3. Update `wrangler.toml`
Add the `nodejs_compat` flag required by better-auth (AsyncLocalStorage):
```toml
compatibility_flags = ["nodejs_compat"]
compatibility_date = "2024-09-23"
```
Add `[vars]` section placeholder comment noting that secrets (DATABASE_URL, DATABASE_URL_UNPOOLED, BETTER_AUTH_SECRET, BETTER_AUTH_URL, ALLOWED_EMAILS) must be set via `wrangler secret put`.

### 4. Update `next.config.ts`
Remove `output: "standalone"` — the Workers build replaces the standalone Docker output:
```ts
const nextConfig: NextConfig = {
  reactCompiler: true,
  // output: "standalone" removed — Workers build via @opennextjs/cloudflare
};
```

### 5. Rewrite `src/lib/shiki.ts`
Switch from `createHighlighter` (full bundle, Oniguruma WASM) to `createHighlighterCore` with the JavaScript regex engine and fine-grained language imports. Key changes:
- Import from `shiki/core` instead of `shiki`
- Use `createJavaScriptRegexEngine` from `shiki/engine/javascript` (no WASM)
- Import only the 21 languages in `COMMON_LANGUAGES` explicitly
- Import only the `one-dark-pro` theme
- Preserve the singleton pattern and `highlightCode` function signature

**Note:** Verify exact import paths against shiki v4 API before writing (they may be `shiki/langs/typescript` or `@shikijs/langs/typescript` depending on v4 package structure). Query Context7 for shiki v4 fine-grained bundle at implementation time.

### 6. Remove `pg` from dependencies
`pg` uses the Node.js `net` module and will fail to bundle for Workers. It was left over from the pre-Neon setup — `src/db/index.ts` no longer uses it.
```
npm uninstall pg @types/pg
```

### 7. Update `package.json` scripts
Add Workers-specific scripts alongside existing ones:
```json
"build:worker": "opennextjs-cloudflare build",
"deploy": "opennextjs-cloudflare deploy",
"preview": "opennextjs-cloudflare preview"
```

### 8. Build and fix
```
npm run build:worker
```
Fix any bundler errors. Common issues to watch for:
- Any remaining Node.js-only imports surfaced by the Workers bundler
- Shiki import path mismatches
